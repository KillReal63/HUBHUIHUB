# «На столе»: прототип питания

6 октября 2026. Четвёртое приложение хаба, `/food/`. Plain HTML/CSS/JS, файлы `dist/food/`. Четыре оформления через настройки: Фисташка, Черника, Бумага, Вечер.

## Что можно попробовать

- Дневник по датам: завтрак, обед, ужин, перекус; название, время, заметка, необязательные калории. Сумма относится только к заполненным записям, целей питания и рекомендаций нет.
- Запасы: количество в г/мл/шт, дата покупки, ожидаемая длительность, необязательный срок годности. Пополнение добавляет количество к учтённому остатку.
- Запись сегодняшней порции может списывать один выбранный продукт. Удаление записи возвращает количество. Рецепты из нескольких ингредиентов пока не реализованы.
- Предпросмотр будущих покупок по запасам. Записи в `tasks_state` не создаются; push не отправляются.
- Пример загружается отдельной кнопкой, только в пустой дневник. Очистка примера включает внесённые в него изменения и требует подтверждения.

Данные хранятся только в localStorage `my-day-food-prototype-v1`, оформление — `my-day-food-theme`. Нет серверной синхронизации, резервирования этих записей и миграции между устройствами. Используется существующий общий вход; Nginx защищает `/food/`, клиент проверяет сессию до показа записей. Не выдавать прототип за серверный дневник.

Расход в день = размер последней покупки / указанное число дней. Оценка даты следующей покупки = дата последнего учёта + округлённое вверх количество оставшихся дней. Прошедшее время уменьшает показанную оценку дней, но не списывает физический остаток автоматически. Списание порции или её возврат обновляют дату учёта. Это ручная оценка, не обученная статистика. При пополнении сохраняется более ранний срок годности оставшегося продукта.

## Что подсмотрели и что подходит нам

Официальные источники просмотрены 6 октября 2026:

- [Cronometer: Diary Overview](https://support.cronometer.com/hc/en-us/articles/360018171731-Diary-Overview) — учёт съеденного и обзор питания. Для нас: быстрое добавление, заметки и необязательные числа; не начинать с огромного каталога нутриентов.
- [KitchenPal](https://kitchenpalapp.com/en/) — домашние запасы, сроки годности, покупки, планирование питания. Для нас: «сначала использовать» и видимый запас в днях.
- [Paprika: руководство iOS](https://paprikaapp.com/help/ios/) — меню, рецепты, список покупок с учётом кладовой. Для нас: список недостающих продуктов из выбранных блюд на неделю.

Предлагаемая очередь развития: повтор вчерашнего завтрака и любимые блюда; партии продуктов с отдельными сроками; история покупок и фактический интервал расхода; план меню и объединённый список покупок; расходы на продукты. Фото и штрихкоды — после удобного ручного ввода.

## Следующий этап: настоящая связь с «Делами»

1. Серверное состояние питания с версиями и 409, аналогично делам; отдельная таблица и сохранение часового пояса записи. Общие подписки и ключи не менять.
2. Правило на продукт: фиксированный интервал (например, каждые 3 дня) **или** по прогнозу остатка. Пользователь задаёт время и выбирает режим; не подменять интервал днями недели. В текущем API дел нет повтора «каждые N дней».
3. Одно активное дело на продукт с устойчивым `source`/идентификатором. Обновление прогноза меняет существующее дело, не создаёт дубликаты. Фоновая обработка на сервере, чтобы закрытое приложение не останавливало напоминания.
4. «Купил» запрашивает количество, пополняет запас, завершает связанную покупку и рассчитывает следующую. «Выполнено» в обычных делах само по себе не должно придумывать количество купленного.
5. Пауза правила, перенос покупки и поведение при ручном удалении связанного дела должны быть явными. Сохранить общий приватный текст уведомлений.

Связь с тренировками можно начать с просмотра питания в день тренировки; автоматические нормы калорий или изменения приёма лекарств не входят в эту задумку.

## Локальная проверка

`node preview-food.cjs` → `http://127.0.0.1:4176/food/`. Изолированный просмотр с подменой проверки сессии; не публиковать этот сервер. Проверить пример, добавление продукта, списание/возврат порции, пополнение, покупки, сохранение после обновления, четыре оформления на 320/390 px.
