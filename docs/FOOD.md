# Питание

Дневник, запасы, любимые блюда, меню и покупки. Интерфейс — `dist/food/`, серверная логика — `backend/wellness.py`. Изменения подготовлены локально; публикация не выполнена.

## Возможности

- Дневник по датам: название, время, приём пищи, заметка и необязательные калории.
- Продукты в граммах, миллилитрах или штуках; каждая покупка — отдельная партия с датой и сроком.
- Списание сегодняшней порции из непросроченных партий, начиная с ближайшего срока; удаление записи возвращает количество в исходные партии.
- Просмотр партий и последних 50 движений продукта; полная сохранённая история входит в экспорт. Остаток отдельной партии можно списать вручную.
- Любимые блюда, ингредиенты на порцию, быстрый повтор и недельное меню.
- Меню распределяет остаток партий между блюдами один раз, учитывая сроки на дату блюда. Повтор рецепта не списывает ингредиенты автоматически.
- Четыре оформления с локальным сохранением темы.

## Автопокупки

В карточке продукта открой «Автопокупка», включи правило, укажи минимум, целевой запас, время и часовой пояс. При остатке не выше минимума создаётся разовое дело. Режим прогноза дополнительно учитывает расход и число дней до окончания. Прогноз не списывает физический остаток; при нулевом расходе используется минимум.

В «Покупках» можно открыть дело или нажать «Купил» и ввести количество. Достаточное пополнение закрывает покупку, частичное обновляет потребность. Простое выполнение дела не меняет запас. Удаление/выполнение подавляет повтор в том же цикле; правило можно явно возобновить. Перенос даты сохраняется.

Просроченные партии исключаются из доступного количества, но остаются в учёте. Изменение количества не повторяет уведомление на прежнее время. Если выбранное время сегодня прошло, напоминание будет завтра; задача сразу видна в «Дела вообще».

## Сохранение и перенос

Используется `/api/food`, общая авторизация и версии. Сохранение подтверждается сервером. При 409 загружаются свежие данные, действие нужно повторить. Неопределённая отправка повторяется с тем же идентификатором; это не полноценный офлайн-режим.

Старые локальные записи переносятся явной кнопкой. Исходная копия сохраняется, повторный импорт не дублируется, конфликт останавливает импорт. Старое предложение покупки не активирует реальные задачи без настройки. Возврат старой порции с неизвестной партией создаёт партию без срока годности.

## Проверка

```text
node test-food.cjs
python -m unittest discover -s backend -p "test_wellness.py"
python test-persistence.py
python preview-local.py
```

Локальный просмотр использует временную базу и не отправляет уведомления. Ограничения, восстановление и состав публикации — в [описании P0/P1](P0-P1.md).
