# Что посмотреть

Реализовано локально 22 октября 2026. На VPS в рамках этой задачи не опубликовано, на реальном iPhone не проверено.

## Возможности

- Отдельное приложение `/watch/` и ссылка из хаба, общий вход.
- Ручное добавление: название, тип (фильм, сериал, другое), необязательные заметка и ссылка.
- Два списка: «Хочу посмотреть» и «Просмотрено». Просмотренную запись можно вернуть, отредактировать или удалить с подтверждением.
- Новые записи добавляются в начало. Изменение статуса сохраняет порядок записей.
- Сброс в настройках удаляет только записи этого приложения после подтверждения.
- Используется общий размер текста. Внешний поиск, загрузка обложек и отдельные уведомления не входят в первую версию.

## Хранение и синхронизация

`GET/POST /api/watch`, общая серверная сессия и проверка Origin для POST. Данные — строка `watch` в существующей таблице `module_state`, состояние `{items: [...]}`. Запись содержит `id`, `title`, `kind` (`film|series|other`), `note`, `url`, `watched` (boolean).

До 1000 записей; название до 160 символов, заметка до 2000, ссылка до 2048. Разрешены полные HTTP(S)-ссылки без логина и пароля. Сервер не загружает адреса ссылок. Интерфейс выводит пользовательский текст через `textContent`, открывает ссылки с `noopener noreferrer`.

`HubStore` подтверждает сохранение ответом сервера, обновляет список при фокусе и каждые 30 секунд вне открытых диалогов. POST использует версию и идентификатор операции. Конфликт возвращает 409 с актуальным состоянием; введённые в форме поля остаются для явного повтора. При потерянном ответе повтор используется с тем же идентификатором, без дублирования записей. Офлайн-редактирования нет. При 401 приложение закрывает форму и направляет на общий вход.

## Резервные копии

Экспорт использует `schema: 2` и включает пять серверных состояний; отдельное приложение покупок хранится внутри состояния food. Восстановление поддерживает новые копии и старые `schema: 1` без «Что посмотреть». Старая копия **не меняет** текущие записи «Что посмотреть»; предпросмотр явно сообщает об этом. Неполная копия schema 2 отклоняется. Контроль версий и защитная копия перед восстановлением сохраняются.

## Публикация

Обновлять согласованно:

- `backend/watch.py`, `backend/wellness.py`, `backend/server.py`, `backend/data_portability.py`;
- весь `dist/watch/`;
- `dist/hub/index.html`, `hub.js`, `chrome.js`, `data.js`;
- `deploy/nginx-https.conf`: защищённый раздел `/watch/`, редирект `/watch`.

Существующие общие `dist/hub/sync.*`, `preferences.js`, `chrome.css`, `hub.css` должны быть на сервере. Таблица и пустая строка приложения создаются штатной инициализацией без сброса остальных данных. Нужны резервная копия файлов и согласованный снимок SQLite, перезапуск API, `nginx -t` перед reload. Старый `publish-hub.sh` остаётся частичным и не устанавливает весь этот набор. Изменения не требуют новых серверных зависимостей или смены PWA/подписок.

## Проверки

Сервер: `python -m unittest discover -s backend -p "test_*.py"`.

Клиентская навигация: `node test-hub.cjs` и `node test-paths.cjs`.

Браузер: запустить `python preview-local.py --port 4187`, затем `python test-watch.py` из другого терминала. Проверка использует временную базу, не отправляет push и не открывает внешние ссылки. Нужны Python Playwright и Chromium; допускается `CHROMIUM_EXECUTABLE`. Проверяются запись/редактирование, статусы, конфликт, потеря ответа, экспорт, сброс и геометрия 320/390 px при обычном и увеличенном тексте.
