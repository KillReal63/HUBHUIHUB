# Покупки

Реализовано локально 29 октября 2026. Отдельное приложение доступно по `/shopping/`; публикация в рамках этой задачи не выполнялась.

## Пользовательский сценарий

- На главном экране находится текущий список одного похода.
- Позиции добавляются вручную либо из подсказок «Пора пополнить» в питании.
- Купленное отмечается галочкой. Удаление убирает ошибочную позицию, но не создаёт запись истории.
- «Завершить поход» доступно после первой отметки. В историю сохраняется весь список: купленные и оставшиеся позиции.
- История показывает до 200 последних походов, дату, количество купленного и состав списка.
- Прошлый поход можно повторить целиком; отдельную позицию можно вернуть в текущий список. Уже присутствующие названия повторно не добавляются.
- Очистка истории не затрагивает текущий список. Отдельный сброс приложения очищает оба раздела.

## Данные и совместимость

Приложение использует существующий `/api/food`, версии состояния и защиту повторов операций. Это позволяет сохранить прежний ручной список без отдельной миграции.

- `manualShopping: [{id, name, done}]` — текущий поход, до 500 позиций.
- `shoppingTrips: [{id, completedAt, items: [{id, name, bought}]}]` — до 200 походов и 10 000 позиций суммарно.
- Команды: `shopping-add`, `shopping-check`, `shopping-delete`, `shopping-finish`, `shopping-repeat`, `shopping-history-clear`, `shopping-reset`.

Оба поля необязательны для старых состояний. Старый клиент, который сохраняет питание целиком, не удаляет текущий список или историю. Сброс питания сохраняет покупки; они удаляются только из настроек приложения «Покупки». Экспорт включает оба поля. При восстановлении старой копии без этих полей текущие покупки и история сохраняются.

## Связь с питанием

В питании вкладка «Покупки» ведёт в отдельное приложение. «Пора пополнить» остаётся отдельной вкладкой питания: недостающий ингредиент меню или продукт с активной автопокупкой добавляется в текущий список одной кнопкой. Добавление в список само по себе не меняет запасы и не завершает связанное дело.

## Оформление

Приложение поддерживает четыре общих профиля хаба: «Воздух», «Сад», «Плитки» и «Вечер». Размер текста берётся из общей настройки. До загрузки состояния показывается скелет; фон блокируется при открытом диалоге.

## Проверки и публикация

- Сервер: `python -m unittest backend.test_wellness` из окружения, где `backend` доступен в `PYTHONPATH`, либо общий `python -m unittest discover -s backend -p "test_*.py"`.
- Браузерный сценарий: `python preview-local.py --port 4188`, затем `python test-manual-shopping.py`. Он использует временную базу и не отправляет push.
- Синтаксис: `node --check dist/shopping/shopping.js`.

Публиковать согласованно `backend/{wellness.py,data_portability.py}`, `dist/shopping/`, обновлённые `dist/food/`, `dist/hub/`, `dist/sw.js` и `deploy/nginx-https.conf`. После установки backend нужен перезапуск API; перед reload Nginx требуется `nginx -t`.
