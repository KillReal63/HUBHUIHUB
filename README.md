# Хаб повседневных приложений

Веб-приложение с единым входом для управления повседневными задачами, расписанием приёма лекарств, тренировками, питанием, покупками и списком того, что посмотреть.

Поддерживаются мобильные устройства, установка в качестве PWA, темы оформления и уведомления.

## Текущие возможности

| Раздел | Возможности | Хранение данных |
|---|---|---|
| Хаб | Авторизация, навигация, сводка «Сегодня», настройки оформления и уведомлений | Серверные данные модулей, сессия, локальные настройки |
| Лекарства | Расписания приёма, открытый календарь, курсы, отметки, пропуски, переносы, поиск и страницы истории | Сервер, SQLite |
| Дела | Разовые и повторяющиеся задачи, заметки, статусы, история и повторные уведомления | Сервер, SQLite |
| Тренировки | Программы по дням, каталог упражнений, подходы, рабочие веса, текущие отметки и история | Сервер, SQLite |
| Питание | Дневник, запасы, сроки, любимые блюда, календарь меню и копирование блюд | Сервер, SQLite |
| Покупки | Текущий поход, отметки, подсказки из питания и история завершённых походов | Сервер, SQLite |
| Что посмотреть | Фильмы, сериалы и другие записи, заметки, ссылки, списки запланированного и просмотренного | Сервер, SQLite |

История тренировок реализована локально 29 октября 2026: отдельные сессии по датам, фактические подходы, повторения и вес, предыдущие результаты и таймер отдыха. Прогресс сохраняется на сервере явной кнопкой; завершённые сессии не меняются вместе с программой. На VPS не опубликовано. Подробности — [история тренировок](docs/GYM-HISTORY.md).

Сводка «Сегодня» реализована локально 24 октября 2026: хаб показывает дела, лекарства, выбранную тренировку, меню и продукты с близким сроком годности. Каждая строка открывает исходную запись, данные обновляются с сервера. На VPS не опубликовано. Подробности — [сводка «Сегодня»](docs/TODAY.md).

Отдельное приложение «Покупки» реализовано локально 29 октября 2026: текущий список одного похода, отметки купленного, завершение похода, история и повтор всего списка или отдельной позиции. Прежний список питания используется без миграции; подсказки «Пора пополнить» добавляются в него одним нажатием. На VPS не опубликовано. Подробности — [документация покупок](docs/SHOPPING.md).

Обновление интерфейса от 29 октября 2026 реализовано локально: приложения показывают стабильный скелет до загрузки данных, фон страницы блокируется под модальными окнами, календарь лекарств и меню открыт сразу. История лекарств получила поиск по дате и пагинацию. В тренировках новые дни именуются автоматически, каталог предлагается раньше ручной формы, удаление дня доступно из программы, а перенос локальных записей находится в настройках. В питании автопополнение вынесено отдельно, блюдо можно перенести или повторить сразу по нескольким дням. На VPS не опубликовано.

Общее оформление настраивается в хабе: при включённой синхронизации выбранный профиль применяется ко всем приложениям, а прежние индивидуальные темы сохраняются и возвращаются после отключения. Ключи устройства — `my-day-theme-sync` и `my-day-theme-profile`.

### Автоматизация покупок

Модуль питания интегрирован с разделом дел.

- Автоматическое создание задач на покупку при достижении минимального остатка или по прогнозу расхода.
- Предотвращение дублирования активных задач для одного продукта.
- Синхронизация пополнения запасов и связанных задач.
- Учёт продуктов отдельными партиями со сроками годности.
- История изменения запасов и расхода.
- Расчёт недостающих ингредиентов для запланированного меню.

Прогноз расхода строится на введённых данных. Время само по себе не уменьшает фактический остаток продукта.

### Резервное копирование

Настройки хаба позволяют экспортировать записи всех приложений и восстанавливать данные с предварительной проверкой. Покупки входят в состояние питания; восстановление старой копии без покупок сохраняет текущий список и историю. Новые копии используют schema 2; восстановление старой schema 1 также сохраняет текущие записи «Что посмотреть».

Подключение внешнего сервера резервного копирования предусмотрено отдельно.

## Данные и синхронизация

- Все пять функциональных модулей используют серверное хранение данных и контроль версий состояния.
- Сохранение изменений подтверждается сервером.
- При конфликте версий необходимо обновить данные и повторить изменение.
- Данные обновляются при возвращении на страницу и периодически, если не открыта форма редактирования.
- Предусмотрен перенос старых локальных данных питания и тренировок из браузера с проверкой повторного импорта и конфликтов.
- Исходные локальные записи сохраняются при переносе.
- Полноценное офлайн-редактирование с общей очередью отложенных изменений пока не реализовано.

### Уведомления

Используется общая инфраструктура уведомлений.

- Уведомления не раскрывают названия лекарств и задач.
- Расписания учитывают соответствующие часовые пояса.
- Фактическая доставка зависит от разрешений браузера, операционной системы и устройства.

## Локальный запуск

Для локального просмотра рекомендуется использовать отдельное Python-окружение.

Установить зависимости:

```bash
python -m pip install -r backend/requirements.txt
```

Запустить приложение из корня проекта:

```bash
python preview-local.py
```

Локальный адрес:

`http://127.0.0.1:4185/`

Режим предназначен для изолированного просмотра функциональных модулей.

Особенности:
- Используется временная база данных.
- Применяется тестовая сессия.
- Отправка push-уведомлений отключена.
- Тестовые записи удаляются после завершения работы.

Локальный просмотр не предназначен для публичного размещения.

Отдельные статические просмотры модулей не заменяют полноценный запуск приложения с API.

## Тестирование

### Серверные тесты

```bash
python -m unittest discover -s backend -p "test_*.py"
```

Используются временные базы данных и подмена транспорта уведомлений.

### Клиентские тесты

```bash
node test-cycles.cjs
node test-hub.cjs
node test-push-ui.cjs
node test-paths.cjs
node test-postpone.cjs
node test-tasks.cjs
node test-task-list.cjs
node test-task-moves.cjs
node test-themes.cjs
node test-food.cjs
node test-today.cjs
```

### Браузерные тесты

Для выполнения необходимы Playwright и Chromium.

```bash
python test-interface.py
python test-persistence.py
node test-today-ui.cjs
```

Проверяются взаимодействия интерфейса, сохранение данных, работа с локальным API, конфликтующие изменения, импорт и восстановление.

Автоматические тесты не подтверждают доставку уведомлений на реальные устройства.

Скрипты отправки реальных уведомлений и проверки среды размещения не входят в обычный набор локальных тестов.

## Размещение и сопровождение

Конфигурация развёртывания зависит от целевой инфраструктуры.

Перед публикацией или обновлением необходимо:

1. Проверить конфигурацию целевой среды.
2. Создать резервные копии затрагиваемых файлов.
3. Подготовить согласованную резервную копию базы данных.
4. Выполнить обновление приложения.
5. Проверить доступность интерфейса, API и основных функций.

Скрипты публикации отдельных модулей не заменяют полноценную процедуру развёртывания всего приложения.

### Безопасность

- Учётные данные, секреты и ключи должны храниться вне общедоступной документации.
- Конфигурации конкретной среды должны быть отделены от универсальных настроек проекта.
- Пользовательские записи не должны попадать в репозиторий.
- Резервные копии должны храниться с ограниченным доступом.
- Необходимо сохранять лицензии и уведомления об авторстве сторонних материалов.

Серверное резервирование охватывает данные модулей, перенесённые в SQLite. Локальные данные браузера, не перенесённые на сервер, требуют отдельного сохранения.

## Будущие изменения

Серверная синхронизация питания и тренировок (P0), автопокупки, экспорт, восстановление и партии продуктов (P1) уже реализованы в коде. Ниже перечислены следующие улучшения; наличие в плане не означает, что функция доступна.

| Приоритет | Улучшение | Статус |
|---|---|---|
| P1 | Резервное копирование на отдельный сервер | Отложено до выбора сервера и времени подключения |
| P2 | Общий экран «Сегодня» для всех модулей | Реализовано локально 24 октября 2026, не опубликовано |
| P2 | Журнал тренировок по датам и история подходов | Реализовано локально 29 октября 2026, не опубликовано |
| P2 | Списание ингредиентов рецепта действием «Приготовил» | Реализовано локально 23 октября 2026, не опубликовано |
| P3 | Полноценное офлайн-редактирование с обработкой конфликтов | Запланировано |

Локально реализованы 22 октября 2026: повтор дел каждые N дней (1–365), перенос одного события без сдвига серии, подзадачи с отдельными отметками для каждой даты и увеличенные отступы карточек во всех темах. Изменения ещё не опубликованы на рабочем сайте.

Также локально реализовано приложение «Что посмотреть»: ручное добавление, тип записи, заметка, ссылка, статусы, общее серверное сохранение и резервные копии. Публикация не выполнена; подробности — [документация приложения](docs/WATCH.md).

Отдельное приложение покупок с историей и общий переключатель оформления реализованы локально 29 октября 2026. Повторные уведомления дел и лекарств также реализованы локально: выключены по умолчанию, есть интервалы 10/30/60 минут и свой шаг 1–12 часов, до трёх дополнительных напоминаний. Выполнение дела, отметка или пропуск приёма останавливают повторы; перенос запускает отсчёт от нового времени. На VPS не опубликовано.

Подробности, зависимости и критерии готовности — в [плане развития](docs/plans/roadmap.md).
