# Хаб повседневных приложений

Веб-приложение с общим входом для управления делами, расписанием приёма лекарств, тренировками и питанием. Интерфейс адаптирован для мобильных устройств; предусмотрены установка как PWA, темы оформления и управление уведомлениями на устройстве.

## Текущие возможности

| Раздел | Возможности | Хранение данных |
| --- | --- | --- |
| Хаб | Вход, переход между разделами, настройки уведомлений и оформления | Общая серверная сессия; оформление локально |
| Лекарства | Недельные и циклические расписания, курсы, отметки, пропуски, перенос отдельного приёма или курса, история | Сервер, SQLite |
| Дела | Разовые, ежедневные и еженедельные задачи; заметки; выполнение и отмена отметки; представления на сегодня и за весь период; предстоящие, выполненные и пропущенные события | Сервер, SQLite |
| Тренировки | Программа по дням, каталог упражнений с изображениями, подходы, повторения, вес, заметки и отметки выполнения | Только текущий браузер, localStorage |
| Питание | Дневник, запасы и ручное списание порций, пополнение, сроки годности, любимые блюда, недельное меню и расчёт недостающих ингредиентов | Прототип; только текущий браузер, localStorage |

В питании список покупок по запасам пока является предпросмотром: он не создаёт задачи в разделе дел и не отправляет уведомления. Прогноз расхода основан на введённых пользователем данных; течение времени само по себе не списывает физический остаток. Меню учитывает порции, доступный запас и срок годности на дату блюда.

## Данные и синхронизация

- Лекарства и дела используют версии состояния. Сохранение подтверждается сервером; при конфликте версий требуется обновить данные и повторить изменение.
- Эти разделы обновляются при возвращении на страницу и периодически, вне открытой формы редактирования.
- Общий вход не обеспечивает серверную синхронизацию тренировок и питания. Очистка данных браузера может привести к потере их записей.
- Полноценного офлайн-редактирования и общей очереди отложенных изменений пока нет.
- Часовой пояс дела сохраняется при создании; уведомления лекарств используют часовой пояс подписки устройства.
- Уведомления используют общую инфраструктуру и нейтральный текст без названий лекарств и задач. Фактическая доставка зависит от разрешений и среды устройства.

## Структура проекта

| Каталог или файл | Назначение |
| --- | --- |
| `dist/hub/` | Общий вход, навигация и оформление хаба |
| `dist/` | Интерфейс лекарств, расписания, PWA и общие уведомления |
| `dist/tasks/` | Интерфейс и клиентская логика дел |
| `dist/food/` | Прототип питания и расчёты меню |
| `gym-prototype/dist/` | Тренировки и каталог упражнений |
| `backend/` | API, авторизация, SQLite, расписания, отправка уведомлений и резервирование |
| `deploy/` | Конфигурации размещения и вспомогательные скрипты |
| `docs/` | Документация модулей и исторические материалы |
| `test-*.cjs`, `backend/test_*.py`, `test-interface.py` | Проверки логики и интерфейса |

Frontend написан на HTML, CSS и JavaScript без обязательного этапа сборки. Файлы в `dist/` — редактируемые исходники. Backend использует Python, SQLite и зависимости из `backend/requirements.txt`. Для размещения предусмотрены Nginx и системные службы.

## Локальный просмотр

Из корня проекта, при установленном Node.js:

```text
node preview-focus.cjs
node preview-food.cjs
node gym-prototype/server.cjs
```

Команды запускаются отдельно. Адреса локальных просмотров:

- Лекарства: `http://127.0.0.1:4174`.
- Питание: `http://127.0.0.1:4176/food/`.
- Тренировки: `http://127.0.0.1:4182/gym`.

Это вспомогательные просмотры отдельных интерфейсов, а не полноценный запуск системы. Просмотр лекарств использует синтетические записи, просмотр питания — подмену проверки сессии. Такие серверы не предназначены для публикации. Корневой `server.cjs` предоставляет ограниченный статический просмотр; единой команды локального запуска всего хаба пока нет.

## Проверки

Для серверных тестов установите зависимости в отдельное Python-окружение:

```text
python -m pip install -r backend/requirements.txt
python -m unittest discover -s backend -p "test_*.py"
```

Проверки клиентской логики:

```text
node test-cycles.cjs
node test-hub.cjs
node test-push-ui.cjs
node test-paths.cjs
node test-postpone.cjs
node test-tasks.cjs
node test-task-list.cjs
node test-themes.cjs
node test-food.cjs
```

Для `python test-interface.py` дополнительно нужны Playwright и Chromium. Браузерные проверки используют вымышленные данные и перехват запросов. Серверные тесты используют временные базы и подмену транспорта уведомлений; они не подтверждают доставку на реальное устройство.

`backend/send_test.py` отправляет реальные уведомления и не входит в обычный тестовый запуск. Скрипты `deploy/verify-*.py` обращаются к среде размещения и также не являются изолированными локальными тестами.

## Размещение и сопровождение

Адреса, учётные данные, ключи, содержимое пользовательских записей и параметры конкретной среды не приводятся в этом описании. Их следует хранить отдельно от общедоступной документации и исходного кода.

Конфигурации размещения требуют проверки и настройки под целевую среду. Скрипты публикации отдельных разделов не являются универсальной установкой всего продукта. Перед обновлением нужны резервные копии затрагиваемых файлов и согласованная копия базы. Имеющийся механизм резервирования SQLite не охватывает локальные данные браузера; внешнее хранение копий требует отдельной настройки.

Лицензии и уведомления об авторстве сторонних материалов каталога упражнений находятся рядом с каталогом и должны сохраняться.
