# Вовремя

Рабочий сайт: https://144.31.166.231/vovrema/ . Один личный аккаунт, SQLite, Python с pywebpush и Nginx. Исходники: https://github.com/KillReal63/TABLETOCKA . Дополнительные контейнеры не используются.

## Первый вход

В своём SSH-терминале на VPS получите код командой `cat /var/lib/vovremya/setup-token`. Вставьте код на странице сайта и задайте пароль из 12–256 символов. После активации файл с кодом удаляется, создание второго аккаунта запрещено. Сессия действует 7 дней; пароль хранится как PBKDF2-SHA256 с индивидуальной солью. Cookie Secure/HttpOnly/SameSite=Strict. Записывающие запросы проверяют Origin; попытки входа ограничены.

Старые записи localStorage можно перенести кнопкой после входа. Для переноса открывайте сайт в том же браузере и по тому же адресу, где вводились записи. Исходная локальная копия не удаляется. Изменения подтверждаются сервером; при конфликте версий нужно повторить действие. Синхронизация — при фокусе страницы и каждые 30 секунд вне редактирования.

## Размещение

- `/var/www/vovremya`: статические файлы из `dist/`, включая PWA-манифест, service worker и иконки.
- `/opt/vovremya`: `backend/server.py`, `backend/push_system.py`, `backend/schedule_logic.py`, `backend/backup.py` и отдельное окружение `venv` с зависимостями из `backend/requirements.txt`.
- `/var/lib/vovremya/app.sqlite3`: база, доступная только системному пользователю vovremya и root.
- API: `127.0.0.1:8765`, Nginx проксирует `/vovrema/api/` по HTTPS в `/api/` локального Python-сервера.
- `vovremya-api.service`: сервер с автоматическим запуском и перезапуском.
- `vovremya-backup.timer`: резервная копия ежедневно в 03:00 UTC, 14 последних дневных копий в `/var/lib/vovremya/backups`. Используется SQLite backup API с проверкой целостности. Копии на том же VPS не защищают от потери самого VPS; внешнее резервирование пока не настроено.
- `vovremya-certbot.timer`: проверка продления HTTPS дважды в день. Certbot находится в `/opt/vovremya-certbot`.

Конфигурации в `deploy/`. Для обновления интерфейса загрузите `dist/` в каталог сайта. Для обновления Python-файлов загрузите их в `/opt/vovremya` и выполните `systemctl restart vovremya-api`. Перед изменениями базы создавайте резервную копию. Приватные SSH-ключи, SQLite-файлы и пароли не должны попадать в Git.

## Проверка

`python3 backend/test_server.py` использует отдельную временную базу и проверяет первый вход, сессии, сохранение, конфликт версий, валидацию, ограничение попыток входа и резервную копию. `node --check dist/app.js` и `node --check dist/auth.js` проверяют синтаксис интерфейса. Старый `server.cjs` предназначен только для просмотра статических файлов и не предоставляет API: полноценное приложение работает за HTTPS с Python-сервером.

## Ограничения

Web Push отправляется сервером каждые 20 секунд при наступлении времени приёма. На iPhone нужен iOS 16.4+, установка на главный экран, вход через иконку и разрешение уведомлений. Кнопка проверки отправляет тестовый push. Подписки продолжают работать после выхода и истечения сессии; отключить их можно на странице этого устройства. Часовой пояс каждой подписки обновляется при открытии сайта. Если телефон сменил часовой пояс, откройте сайт для синхронизации. Интернет и системные настройки могут задержать доставку. Просроченные более чем на 5 минут напоминания не отправляются. Три попытки при временном сбое, журнал доставки сохраняется в SQLite. Текст на экране блокировки не содержит лекарств. Реальная доставка на iPhone требует проверки пользователем. Поддержаны службы Apple, Chrome/FCM и Firefox. Сайт не кэширует медицинские записи для офлайн-доступа. Ключ VAPID хранится в `/var/lib/vovremya/vapid.pem` и копируется в защищённый каталог резервных копий; его нельзя публиковать. Дозировки задаёт пользователь по назначению врача. Время расписания относится к часовому поясу устройства.
Тесты push: /opt/vovremya/venv/bin/python test_push.py в тестовом каталоге на сервере. Используется временная база и подмена транспорта, реальные уведомления тестами не отправляются.

## Циклический приём

В форме препарата выберите «Режим приёма → N дней через M дней». Укажите 1–365 дней приёма, 1–365 дней перерыва и первый день приёма. Например, 2 через 3 с 18 сентября: приём 18–19, перерыв 20–22, следующий приём 23–24 сентября. Часы приёма задаются как обычно, конец курса необязателен. В режиме цикла дни недели не ограничивают расписание. Цикл считается по календарным датам от начала курса, а не от отметок «Принято». В дни перерыва сервер не отправляет напоминания. Существующие препараты продолжают использовать свои дни недели.

Дополнительное поле записи: `cycle: {on: N, off: M}`; отсутствие поля означает прежнее недельное расписание. Миграция SQLite не требуется. Проверки: `node test-cycles.cjs` и `python -m unittest discover -s backend -p 'test_*.py'` в Python-окружении с зависимостями из `backend/requirements.txt`. Тесты используют синтетические записи, временные базы и подменённый push-транспорт.

## Категории

В форме записи доступны «Таблетка», «Мазь», «БАД» и «Действие». Категория сохраняется в поле `category` (`pill`, `ointment`, `supplement`, `action`). Для старых записей без этого поля отображается «Таблетка»; её можно изменить. Для действий подробности вместо дозировки необязательны. Отметки: «Принято», «Нанесено», «Выполнено». Все категории используют обычное или циклическое расписание и существующие напоминания.

## Форма курса

Дозировка выбирается из 1/4, 1/2, 1, 2, 3; при редактировании прежняя нестандартная дозировка доступна отдельным вариантом, чтобы не потерять её. Отношение к еде: `meal` = `before`, `after`, `any`. Режим N дней хранит `durationDays` (1–3650), все дни недели и вычисленную дату окончания (дата начала + N − 1). Push использует существующие границы курса. Поле примечания удалено из формы; прежний текст сохраняется при редактировании.


## Пропуски, переносы и доступность

Кнопка «Пропустить» открывает выбор: через час, на день, на два дня, произвольная дата/время или без переноса. Перенос сдвигает выбранный и все последующие неотмеченные приёмы **этого препарата**; циклы и интервалы сохраняются, окончание курса сдвигается. Отмеченные и пропущенные приёмы остаются на зафиксированных датах. Из истории можно отменить пропуск или последний перенос препарата. При редактировании перенесённого курса форма показывает исходные даты и время и сохраняет переносы.

`med.shifts` хранит исходную границу `from`, сдвиг `minutes` и время операции `at`. Ключи приёмов остаются прежними. Необязательные поля состояния `skipped` и `fixed` содержат отметки пропуска и фактические даты отмеченных приёмов. Старый формат читается без миграции SQLite. Записи старых клиентов, теряющие переносы или отметки, отклоняются с просьбой обновить страницу. При выпуске обязательно загрузить новый `backend/schedule_logic.py` вместе с сервером и `dist/postpone.js` вместе с интерфейсом.

Расписание и история доступны раздельно в нижнем меню. В «Настройки → Внешний вид» доступны обычный, крупный и очень крупный текст; выбор хранится на устройстве.

Проверки переноса: `node test-postpone.cjs` и `python -m unittest discover -s backend -p 'test_*.py'`. Покрывают повторный перенос, конец курса, полночь, циклы, DST, неизменность отметок, отмену и доставку без дублей. На Windows для локальных Python-тестов также нужен пакет `tzdata`. Визуальный предпросмотр использует только тестовые данные в памяти; отправка уведомлений там не выполняется.
