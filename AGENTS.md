# «Мой день»: контекст проекта для нового чата

Актуализировано: 19 октября 2026. Прочитай этот файл перед работой, затем открывай только файлы, относящиеся к задаче. История переписки для начала работы не нужна.

## Что это за проект

Личный сайт одного пользователя: общий хаб и четыре приложения — лекарства «Вовремя», напоминания «Дела», тренировки «Ритм» и питание «На столе». Основное устройство — iPhone; пользователь открывает сайт через иконку, добавленную на главный экран из Safari. Общение и интерфейс — на русском. Часовой пояс пользователя — Asia/Dubai; не заменяй им часовые пояса всех записей.

Единственный рабочий репозиторий: https://github.com/KillReal63/HUBHUIHUB, основная ветка `main`. Рабочий сайт: https://144.31.166.231/ . Это существующий работающий продукт с личными данными, а не проект с нуля.

## Поведение и хранение данных

- **Вход:** один существующий аккаунт для всего хаба, прежний пароль от таблеток. Общая cookie `session` с `Path=/`, Secure, HttpOnly, SameSite=Strict; срок — 7 дней. Изменяющие API-запросы проверяют Origin. Не создавать новый аккаунт или отдельный вход для каждого приложения.
- **Таблетки:** записи и отметки на сервере, таблица `state`; есть недельные и циклические расписания, курсы, переносы, пропуски, история. Валидация — в `backend/server.py`. Поля переносов и отметок нельзя терять при сохранении старой формой. В `shifts` поле `scope: "once"` переносит только один приём; `scope: "course"` или отсутствие `scope` сохраняет прежний сдвиг курса. «Через час» и выбранная дата/время — один приём; перенос на 1–2 дня — курс. Старые переносы автоматически не преобразуются. Расчёт совпадает в `dist/schedule.js` и `backend/schedule_logic.py`.
- **История таблеток:** интерфейс показывает события с 1 октября 2026 (по дате отметки на устройстве). Сентябрьские отметки и переносы остаются в базе для корректного расчёта курса; это фильтр отображения, не удаление данных.
- **Дела:** записи в отдельной таблице `tasks_state`, API `/api/tasks`. Разовые, ежедневные и по дням недели; название, заметка, дата, время. Выполнение закрывает конкретный день, его можно отменить. Часовой пояс фиксируется при создании дела; при поездке не меняется автоматически. Два периода: «Дела сегодня» (по умолчанию, дата в часовом поясе дела) и «Дела вообще». Внутри — «Предстоящие» (по умолчанию), «Выполненные», «Пропущенные»; отдельной вкладки «Все» нет. Пропущенные — невыполненные даты с прошедшим временем по часовому поясу дела; это вычисляемое состояние, не отдельная серверная отметка. Предстоящие показывают ближайший ещё не прошедший невыполненный повтор. Выполненные и пропущенные ограничены последними 100 записями каждый. Удаление из списка и формы требует подтверждения и удаляет всё дело с повторами и отметками.
- **Синхронизация:** все четыре модуля используют номер версии; конфликт возвращает 409. Изменение считается сохранённым после ответа сервера. Обновление при фокусе и примерно каждые 30 секунд, кроме открытой формы. Полноценного офлайн-редактирования нет.
- **Тренировки:** программа и отметки сохраняются на сервере через /api/gym в module_state, с общей сессией, версиями и 409. Исходная локальная копия переносится явной кнопкой, не удаляется и не импортируется повторно. Конфликтующие записи не перезаписываются. Новая программа пустая; дни допускают weekday: null или 0–6. Каталог, редактор и отдельный просмотр фото сохранены; LICENSE.txt и NOTICE.txt не менять. Это локальная реализация, публикация обновления не выполнена.
- **Темы дел:** настройки через шестерёнку, «Воздух», «Шалфей», «Ирис», «Графит». «Графит» сохраняет прежнюю компактную панель; «Воздух» — открытый список, «Шалфей» — зелёные карточки с меткой времени, «Ирис» — список с крупной типографикой. Действия выполнения и удаления расположены справа. Файлы `dist/tasks/themes.*`, выбор хранится локально под `my-day-tasks-theme`. Другие приложения имеют свои темы; общего переключателя всех приложений пока нет.
- **Питание:** серверное состояние /api/food с версиями. Продукт содержит партии с количеством, датой и сроком. Порция списывает ближайшие непросроченные партии; удаление возвращает их. В карточке — партии, история и автопокупка (минимум/цель или прогноз, время, часовой пояс). Связь с делом в food_links, один текущий цикл покупки на продукт; сохранение атомарно. Выполнение/удаление подавляет повтор в том же цикле, перенос сохраняется. Достаточное пополнение закрывает покупку; простое выполнение дела не меняет запас. Новое правило выключено. Старое предложение покупки при импорте не включает задачи. Фоновый пересчёт работает при закрытом приложении; ошибка питания не останавливает остальные уведомления. Меню учитывает партии, но не списывает ингредиенты. Подробности — docs/FOOD.md и docs/P0-P1.md.

- **Общий интерфейс:** в хабе хедер «Мой день», в четырёх приложениях — ссылка «Вернуться в хаб»; везде SVG-шестерёнка. У хаба четыре темы (Воздух, Сад, Плитки, Вечер), `dist/hub/themes.*`, локальный ключ `my-day-hub-theme`. В настройках — общий аккордеон «Уведомления на этом устройстве»: без подписки открыт, после включения сворачивается, последующее ручное раскрытие сохраняется до смены состояния. В тренировках выбор оформления перенесён в настройки; постоянное окно настроек исключено из удаления динамических диалогов.

## Что важно сохранить в уведомлениях

- Общая серверная отправка раз в 20 секунд, окно опоздания — 5 минут, до трёх попыток при временной ошибке. Журнал доставки защищает от повторной отправки. Выполненные записи не должны порождать уведомления.
- Используются существующие подписки и VAPID-ключ. Подписки продолжают работать после выхода из аккаунта; отключение — отдельным действием на устройстве.
- PWA `id`, `start_url`, `scope` сейчас `/`. Новые подписки используют корневой `/sw.js`; живые старые подписки worker со scope `/vovrema/` сохраняются. Не менять id, scope и не сбрасывать подписки ради косметической переработки.
- Совместимый API `/vovrema/api/` остаётся. Старые уведомления без URL открывают таблетки. Уведомления дел открывают `/tasks/?task=ID`. Worker разрешает только ожидаемые адреса того же сайта.
- На экране блокировки — общий текст, без названия лекарства или дела. Не добавлять личные подробности в push без запроса пользователя.
- Лекарства используют часовой пояс подписки, дела — часовой пояс записи. Эти модели времени различаются намеренно.
- Пользователь сообщил о получении тестового push после установки хаба. Регулярная доставка на реальном iPhone не подтверждается модульными тестами; не выдавай тест с подменой транспорта за проверку телефона.

Секреты и личные данные не коммитить и не выводить в сообщения. Использовать уже настроенный доступ, если он доступен и действие разрешено задачей; не просить присылать приватный ключ в чат. Этот файл сам по себе не даёт разрешения на публикацию или другие внешние действия — учитывай запрос и уже данные пользователем разрешения.

`deploy/publish-hub.sh` и `deploy/publish-tasks.sh` — **частичные скрипты релиза**, не универсальная установка всех приложений. Перед запуском прочитай список устанавливаемых файлов и ожидаемый состав архива. В частности, они не публикуют каталог тренировок. Для статических правок не нужен рестарт backend. Для конфигурации Nginx — `nginx -t` до reload; для Python — restart API после установки всех требуемых модулей. Не откатывать всю рабочую SQLite-базу автоматически: это потеряет записи, сделанные после резервной копии.

Не копируй устаревшие версии общего backend, worker или Nginx из исторических репозиториев при обновлении одного раздела. Внешнее резервирование личных данных отдельно от VPS в этом контексте не подтверждено; Git хранит только код.

## Проверки и локальный просмотр

Из корня репозитория, в Python-окружении с зависимостями проекта:

```text
python -m unittest discover -s backend -p "test_*.py"
node test-cycles.cjs
node test-hub.cjs
node test-push-ui.cjs
node test-paths.cjs
node test-postpone.cjs
node test-tasks.cjs
node test-task-list.cjs
node test-themes.cjs
node test-food.cjs
```

Браузерные проверки: `python test-interface.py` (дополнительно установленный Playwright и Chromium). Использует вымышленные данные и перехват запросов, не рабочий API; скриншоты в `.hub-review/interface-checks/`. Проверяет мобильную ширину, темы, фильтры дел, пустую программу, сохранение дней, фото и разовый перенос.

На исходном Windows-компьютере Python находится в `.venv/Scripts/python.exe`, на другой машине путь может отличаться. Проверять синтаксис изменённых JS через `node --check <файл>`. При правках UI проверять мобильную ширину, формы, контраст и выбранную тему. Выбирай проверки по изменению; документация не требует запуска всей системы.

Backend-тесты используют временные базы и подменённый push-транспорт. `backend/send_test.py`, наоборот, отправляет реальные уведомления всем подписанным устройствам — не запускать его как обычный тест. `deploy/verify-*.py` предназначены для VPS: используют реальный HTTPS и временную сессию в рабочей базе, которую удаляют после проверки.

- Таблетки: `node preview-focus.cjs` → `http://127.0.0.1:4174`, синтетические данные в памяти; не публиковать preview на VPS.
- Полный локальный просмотр: python preview-local.py, http://127.0.0.1:4185/; временная база и тестовая сессия, push отключён. Не публиковать. Старые статические серверы питания/тренировок не предоставляют новый API.
- Корневой `server.cjs` — старый ограниченный статический просмотр, **не полный запуск хаба**. Полный временный локальный просмотр запускается через python preview-local.py. Для UI-тестов дел использовался временный mock-сервер; его нет среди поддерживаемых инструментов репозитория.
