## Что это за проект

Личный сайт одного пользователя: общий хаб и четыре приложения — лекарства «Вовремя», напоминания «Дела», тренировки «Ритм» и прототип питания «На столе». Основное устройство — iPhone; пользователь открывает сайт через иконку, добавленную на главный экран из Safari. Общение и интерфейс — на русском. Часовой пояс пользователя — Asia/Dubai; не заменяй им часовые пояса всех записей.

Единственный рабочий репозиторий: https://github.com/KillReal63/HUBHUIHUB, основная ветка `main`. Рабочий сайт: https://144.31.166.231/ . Это существующий работающий продукт с личными данными, а не проект с нуля.

## Поведение и хранение данных

- **Вход:** один существующий аккаунт для всего хаба, прежний пароль от таблеток. Общая cookie `session` с `Path=/`, Secure, HttpOnly, SameSite=Strict; срок — 7 дней. Изменяющие API-запросы проверяют Origin. Не создавать новый аккаунт или отдельный вход для каждого приложения.
- **Таблетки:** записи и отметки на сервере, таблица `state`; есть недельные и циклические расписания, курсы, переносы, пропуски, история. Валидация — в `backend/server.py`. Поля переносов и отметок нельзя терять при сохранении старой формой.
- **История таблеток:** интерфейс показывает события с 1 октября 2026 (по дате отметки на устройстве). Сентябрьские отметки и переносы остаются в базе для корректного расчёта курса; это фильтр отображения, не удаление данных.
- **Дела:** записи в отдельной таблице `tasks_state`, API `/api/tasks`. Разовые, ежедневные и по дням недели; название, заметка, дата, время. Выполнение закрывает конкретный день, его можно отменить. Часовой пояс фиксируется при создании дела; при поездке не меняется автоматически. Вкладки «Все», «Предстоящие» (по умолчанию), «Выполненные», «Пропущенные». Пропущенные — невыполненные даты с прошедшим временем по часовому поясу дела; это вычисляемое состояние, не отдельная серверная отметка. Предстоящие показывают ближайший ещё не прошедший невыполненный повтор. Выполненные и пропущенные ограничены последними 100 записями каждый. Удаление из списка и формы требует подтверждения и удаляет всё дело с повторами и отметками.
- **Синхронизация:** таблетки и дела используют номер версии; конфликт возвращает 409. Изменение считается сохранённым после ответа сервера. Обновление при фокусе и примерно каждые 30 секунд, кроме открытой формы. Полноценного офлайн-редактирования нет.
- **Тренировки:** программа и отметки пока в localStorage конкретного браузера/устройства. Общая авторизация НЕ означает серверную синхронизацию тренировок. Nginx защищает доступ общей сессией. Каталог упражнений и перевод находятся в `gym-prototype/dist/catalog/`; сохранять LICENSE.txt и NOTICE.txt.
- **Темы дел:** настройки через шестерёнку, «Воздух», «Шалфей», «Ирис», «Графит». «Воздух» сохраняет карточки, «Шалфей» — ежедневник, «Ирис» — временная лента, «Графит» — компактная панель. Действия выполнения и удаления расположены справа. Файлы `dist/tasks/themes.*`, выбор хранится локально под `my-day-tasks-theme`. Другие приложения имеют свои темы; общего переключателя всех приложений пока нет.
- **Питание:** прототип дневника, запасов, любимых блюд, недельного меню и покупок. Опубликован на VPS 6 октября 2026. Данные только в localStorage `my-day-food-prototype-v1`; четыре оформления под ключом `my-day-food-theme`. Используются общий вход и защита Nginx. Связь с «Делами» — только предпросмотр: реальные дела и уведомления не создаются. Расход задаётся вручную; запись порции уменьшает запас, удаление возвращает его. Меню рассчитывает недостающие ингредиенты с учётом порций, общего остатка и срока годности на дату блюда. Быстрый повтор любимого блюда не списывает запас автоматически. Ограничения и план интеграции — `docs/FOOD.md`.

- **Общий интерфейс:** во всех пяти разделах одинаковый хедер «Мой день» с названием раздела и SVG-шестерёнкой; на главной странице подпись раздела отсутствует. В настройках — общий аккордеон «Уведомления на этом устройстве»: без подписки открыт, после включения сворачивается, последующее ручное раскрытие сохраняется до смены состояния. В тренировках выбор оформления перенесён в настройки; постоянное окно настроек исключено из удаления динамических диалогов.

## Что важно сохранить в уведомлениях

- Общая серверная отправка раз в 20 секунд, окно опоздания — 5 минут, до трёх попыток при временной ошибке. Журнал доставки защищает от повторной отправки. Выполненные записи не должны порождать уведомления.
- Используются существующие подписки и VAPID-ключ. Подписки продолжают работать после выхода из аккаунта; отключение — отдельным действием на устройстве.
- PWA `id`, `start_url`, `scope` сейчас `/`. Новые подписки используют корневой `/sw.js`; живые старые подписки worker со scope `/vovrema/` сохраняются. Не менять id, scope и не сбрасывать подписки ради косметической переработки.
- Совместимый API `/vovrema/api/` остаётся. Старые уведомления без URL открывают таблетки. Уведомления дел открывают `/tasks/?task=ID`. Worker разрешает только ожидаемые адреса того же сайта.
- На экране блокировки — общий текст, без названия лекарства или дела. Не добавлять личные подробности в push без запроса пользователя.
- Лекарства используют часовой пояс подписки, дела — часовой пояс записи. Эти модели времени различаются намеренно.
- Пользователь сообщил о получении тестового push после установки хаба. Регулярная доставка на реальном iPhone не подтверждается модульными тестами; не выдавай тест с подменой транспорта за проверку телефона.

`deploy/publish-hub.sh` и `deploy/publish-tasks.sh` — **частичные скрипты релиза**, не универсальная установка всех приложений. Для конфигурации Nginx — `nginx -t` до reload; для Python — restart API после установки всех требуемых модулей. Не откатывать всю рабочую SQLite-базу автоматически: это потеряет записи, сделанные после резервной копии.

Не копируй устаревшие версии общего backend, worker или Nginx из исторических репозиториев при обновлении одного раздела. Внешнее резервирование личных данных отдельно от VPS в этом контексте не подтверждено; Git хранит только код.

## Проверки и локальный просмотр

Из корня репозитория, в Python-окружении с зависимостями проекта:

```text
python -m unittest discover -s backend -p "test_*.py"
node test-cycles.cjs
node test-hub.cjs
node test-push-ui.cjs
node test-paths.cjs
node test-postpone.cjs
node test-tasks.cjs
node test-task-list.cjs
node test-themes.cjs
node test-food.cjs
```

На исходном Windows-компьютере Python находится в `.venv/Scripts/python.exe`, на другой машине путь может отличаться. Проверять синтаксис изменённых JS через `node --check <файл>`. При правках UI проверять мобильную ширину, формы, контраст и выбранную тему. Выбирай проверки по изменению; документация не требует запуска всей системы.

Backend-тесты используют временные базы и подменённый push-транспорт. `backend/send_test.py`, наоборот, отправляет реальные уведомления всем подписанным устройствам — не запускать его как обычный тест. `deploy/verify-*.py` предназначены для VPS: используют реальный HTTPS и временную сессию в рабочей базе, которую удаляют после проверки.

- Таблетки: `node preview-focus.cjs` → `http://127.0.0.1:4174`, синтетические данные в памяти; не публиковать preview на VPS.
- Питание: `node preview-food.cjs` → `http://127.0.0.1:4176/food/`, локальный просмотр с подменой сессии; не публиковать preview на VPS.
- Тренировки: `node gym-prototype/server.cjs` → `http://127.0.0.1:4182/gym`, локальный статический просмотр без production-авторизации.
- Корневой `server.cjs` — старый ограниченный статический просмотр, **не полный запуск хаба**. Единой команды локального запуска всего продукта пока нет. Для UI-тестов дел использовался временный mock-сервер; его нет среди поддерживаемых инструментов репозитория.
